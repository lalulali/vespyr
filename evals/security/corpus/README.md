> [!NOTE]
> Attack strings below are deliberately **broken with zero-width spaces** (`​`) so
> the README does not self-flag when the corpus root is scanned (F-10). The

**Invariants (CI-enforced by `node .agents/scripts/check_corpus_invariants.js`):**
- Every rule in `audit-spec.json` has >=1 positive fixture (in `positive/`) and >=1 negative fixture (in `negative/`).
- Positive fixtures MUST produce a finding; negative fixtures MUST NOT (exit 0 on a negative-only scan).
- Negative fixtures include: fake-harness name (must not match pattern table), low-entropy secret (regex matches, entropy < threshold -> NOT a finding).

## Known-FP notes

- **INJ-OBFUSC (base64-blob heuristic) is FP-prone on long tokens** (02f §10,
  supply-chain-audit-spec §7). Scanner suppression layers (F-3, Victor):
  1. token-fragment guard — a purely base64-class match immediately preceded
     on the line by two token-continuation chars (`[A-Za-z0-9_-]`) is a
     fragment of a longer credential-shaped token (e.g. the `ghp_` token in
     `positive/inj-secret.md` fires **only** INJ-SECRET, never INJ-OBFUSC);
  2. structural guard — a match must contain a digit or `+/=`, mix upper/lower
     case, and contain neither `//` nor `.` to count as an obfuscation blob
     (URLs, absolute paths, camelCase-acronym runs are excluded).
  Remaining documented FP classes (3 findings on `.agents`, accepted):
  camelCase-acronym word runs joined by single `/`, URL fragments, long POSIX
  paths. A corpus negative for the word-run class is under the growth rules.
- **INJ-PATH is filename-scoped ONLY** (P1-3 narrowed, supply-chain-audit-spec §7):
  applied to filenames during the walk, never content lines or interpolated
  identifiers — `$`/parens in natural language are NOT findings.
