# AI Agent Framework Comparison: Vespyr · ECC · BMAD · Ruflo

> **Status:** Comparative Analysis — Phase 2 Strategy
> **Date:** 2026-06-23
> **Scope:** Side-by-side evaluation of four AI agent frameworks in the user's local workspace, with synthesized recommendations for Vespyr's evolution.
> **Author:** @researcher (via @vespyr analysis pipeline)

---

## 0. Executive Summary

This document compares four AI agent frameworks — **Vespyr**, **ECC** (Everything Claude Code), **BMAD** (Breakthrough Method for Agile AI-Driven Development), and **Ruflo** (formerly Claude Flow) — along the dimensions of architecture, strengths, weaknesses, key features, and "excellent" documents. The four frameworks occupy four distinct positions in the agent-framework design space:

| Framework | Core Bet | Primary Output |
|---|---|---|
| **Vespyr** | "Most agent failures come from one model doing everything. Force a hard split between *reasoning* and *I/O* via permission denial." | Installable CLI + 21 personas + Socratic methodology + 24 workflow skills |
| **ECC** | "An AI coding agent should be an *operating system*: curated catalog of specialists, hooks, manifests, multi-harness." | Plugin for 9+ harnesses with 64 agents / 262 skills / 84 commands |
| **BMAD** | "LLMs drift. Counter with *micro-file* step architecture, persona-channeled agents, and locked terminology." | Methodology library — 119 skills / 25+ named agents, 8 modules, prompt-engineering-first |
| **Ruflo** | "Wrap Claude Code with consensus, vector memory, federated agents, and zero-trust governance — make a *meta-harness*." | TypeScript monorepo with 314 MCP tools, AgentDB memory, SONA learning, 33 plugins |

**The single biggest takeaway:** each framework has a *real, defensible* core insight that the other three lack. None is a strict superset. The interesting question for Vespyr is **which insights to adopt from each**, not which to copy wholesale.

## 1. What Each Framework Is

### Vespyr
A **platform-agnostic, file-based multi-agent orchestration system** packaged as `npx vespyr`. It scaffolds `.agents/` with 21 specialized Markdown-defined personas, 24 workflow skills, 41 artifact templates, and 18 Node.js helper scripts. The central claim: enforce a *physical* separation between reasoning agents (no `bash`/`edit` permissions) and cheap I/O sub-agents (`@reader`, `@writer`, `@executor`). Combined with a 3-tier progressive memory layer, Socratic methodology, and pipeline state machine, it claims 85–95% token savings and is designed to work across 8+ AI harnesses (OpenCode, Claude Code, Cursor, Windsurf, GitHub Copilot, Kiro, Hermes, OpenClaw).

### ECC (Everything Claude Code)
An **open-source Claude Code plugin** evolved from 10+ months of daily use. At v2.0.0 it ships **64 specialist sub-agents, 262 markdown skills, 84 slash commands, ~30 runtime hooks, 10 JSON Schemas, a 24-module selective-install system, a Rust alpha TUI control plane, and a Python LLM provider abstraction**. It's designed to be a "harness-native operator system" that works across 9+ AI harnesses (Claude, Cursor, Codex, OpenCode, Gemini, Zed, Kiro, Qwen, Trae, Antigravity, Codebuddy) with per-harness config and cross-platform sync scripts. Real engineering taste, not file proliferation.

### BMAD (Breakthrough Method for Agile AI-Driven Development)
A **methodology-and-prompt-engineering framework** installed at v6.8.0 across 8 modules (`core`, `bmm`, `tea`, `bmb`, `automator`, `cis`, `gds`, `wds`). It ships **119 distinct skills, 25+ named agents channeling famous practitioners** (Marty Cagan, Mijo Balic, John Carroll, etc.), and a novel **step-file / micro-file architecture** — one instruction file per step, loaded sequentially — that solves LLM context drift. The "breakthrough" is the disciplined structure, not the executable code: 2 Python scripts, 6 Node.js WDS scaffold scripts, 1 test. BMAD is closer to a *book of well-organized facilitation patterns* than to a software framework.

### Ruflo
A **Claude Code / OpenAI Codex "meta-harness"** distributed as the `ruflo` / `claude-flow` / `@claude-flow/cli` npm packages. It wraps Claude Code with a **314-tool MCP server, 26-command CLI, 17 hooks + 12 background workers, AgentDB + HNSW vector memory, SONA self-learning, 5 consensus algorithms (Byzantine, Raft, Gossip, CRDT, Quorum), zero-trust agent federation with mTLS+ed25519, and 33 Claude Code marketplace plugins**. The marketing is ambitious; the engineering is real but uneven — a sprawling TypeScript monorepo (`v3/@claude-flow/*` workspace) with a 50 KB CLAUDE.md that is unusually honest about which performance claims are measured vs. aspirational.

## 3. Strengths — What Each Does Best

### Vespyr's Strongest Contributions

1. **The "thinking vs. I/O" permission-denial pattern** is the cleanest architectural insight in any of the four. Reasoning agents *physically lack* `bash`/`edit` permissions, forcing delegation to cheap I/O sub-agents. This is rare in the field.
2. **Documentation depth exceptional for the maturity stage.** ~7,500 lines of skill content + ~1,700 lines of agent content. The `founder.md` (259 lines), `memory-controller.md` (336 lines), `validate-idea/SKILL.md` (299 lines), `develop/SKILL.md` (278 lines), `elicitation/SKILL.md` + `methods.csv` (14 KB), and `delegation-pattern.md` (234 lines) are *substantive, opinionated, field-tested* material — not stubs.
3. **The Socratic methodology is well-calibrated.** Anti-sycophancy rules, per-agent socratic files, `grill-me` skill, `pending-questions/<agent>/<topic>.md` system for cross-session continuity.
4. **3-tier progressive memory with filter+archive** (`memory_filter.js` 14 KB, `archive_manager.js` 14 KB, `orchestrator_state.js` 19 KB) is more thoughtful than ECC's session persistence and lighter-weight than Ruflo's HNSW stack.
5. **Honest roadmap with explicit "Backlog (no timeline)"** section. Items move based on real-world problem evidence, not technical interest.
6. **Squad presets (7 named teams)** — `full-team`, `startup`, `build`, `research`, `design`, `ship`, `game-studio` — are a clean way to scope work to context.
7. **Quality gates are explicit and enforceable** — code review → QA → PM sign-off → security (Critical/High blocks) → performance, with max 2 review-loop cycles and named decision authorities.
8. **The `elicitation` skill is genuinely novel** — 5 dynamically-matched methods per artifact (Tree of Thoughts, Pre-mortem, Red Team, Stakeholder Round Table, etc.), with iterative refinement.
9. **The CLI is real production code**, not vapor: 2,563 lines, 16 test cases, harness transpilers (Copilot YAML, Cursor MDC), Windows EPERM fallback.
10. **Strong templates with metadata** — `prd-template.md` (309 lines) has Research Foundation table with `[PENDING]` rows, Hypothesis of Solution with falsifiable predictions, validation plan.

### ECC's Strongest Contributions

1. **Catalog depth, not file proliferation** — 262 skills with median 189 lines; the top of the distribution (`laravel-security` 947 lines, `python-testing` 816, `coding-standards` 550, `agentic-os` 387) reads like a real engineer's notes.
2. **Multi-harness by design, not bolted on** — 9+ first-class adapters with sync scripts (`sync-ecc-to-codex.sh`, `merge-codex-config.js`, `gemini-adapt-agents.js`); dual-export OpenAI gitagent pattern; TypeScript OpenCode plugin with 8 tool implementations.
3. **Real operational maturity** — `catalog:check` enforces README/AGENTS/agent.yaml parity (regression test added 2026-04-08 after #1327); `code-reviewer-false-positive-guard.test.js` enforces anti-spam; `scan-supply-chain-iocs.js` runs IOC scans.
4. **Security-first is real** — `the-security-guide.md` cites specific CVEs (CVE-2025-59536 CVSS 8.7, CVE-2026-21852), Snyk ToxicSkills (3,984 skills scanned, 36% had prompt injection, 1,467 malicious payloads), Microsoft Security "AI Recommendation Poisoning", Hunt.io OpenClaw exposure (17,470 instances).
5. **The `code-reviewer.md` "Common False Positives - Skip These" list** is the most honest single page in the AI-agent ecosystem — 10+ entries including "Consider adding error handling" on paths already handled, "Magic number" for 200/404/etc.
6. **Selective install architecture (24 modules with explicit dependencies)** is unusually good — install just `framework-language` or just `security` without dragging the rest in.
7. **The 3-guide structure (`the-shortform-guide.md` 431 lines, `the-longform-guide.md` 354 lines, `the-security-guide.md` 456 lines)** is a teachable on-ramp.
8. **AURA integration with real threat model** — read-only Python adapter with tests, explicit threat model (spoofed DID, stale verdict, MITM, Sybil, over-trust).
9. **Cross-platform Windows/macOS/Linux** — explicit MSYS2/Git Bash path handling; `scripts/lib/utils.js#getHomeDir()` honors `HOME`/`USERPROFILE` overrides.
10. **Workflow surface policy is explicit** — `skills/` is canonical, `commands/` is legacy. Real architectural decision, not marketing.

### BMAD's Strongest Contributions

1. **The step-file / micro-file architecture is a genuine breakthrough** — one instruction file per step, sequential loading, `stepsCompleted` frontmatter updates. Solves LLM context drift.
2. **Excellent persona engineering** — each agent has a "channeled mentor" (Winston = "favors boring technology for stability," John = Marty Cagan + Teresa Torres, Mary = Porter + Minto, Saga = Mijo Balic, etc.). Consistent, distinctive behavior.
3. **Tri-modal workflows (create / edit / validate)** in TEA — a real pattern for iterative LLM work where most prompt libraries only have create flows.
4. **3-layer TOML customization merge** (`resolve_customization.py` 238 lines) with proper structural rules (scalars override, tables deep-merge, arrays of tables keyed by `code` or `id` merge by key).
5. **WDS (Web Design Studio) is the most complete module** — locked glossary ("One definition per term — no synonyms, no aliases"), agent contracts with explicit "owns / does NOT own" boundaries, 6 Node.js scaffold scripts that enforce deterministic file structure, 474-line design-token architecture doc.
6. **CSV-driven technique libraries** — 61 brainstorming techniques, 70 advanced elicitation methods. Real methodology, not generic instructions.
7. **"Extract, don't ingest" principle** — source docs go to subagents for relevance filtering, parent context stays lean. Genuinely good LLM system design.
8. **Subagent orchestration (Party Mode)** — "When one LLM roleplays multiple characters, the 'opinions' tend to converge and feel performative. By spawning each agent as its own subagent process, you get real diversity of thought."
9. **Decision logs, design logs, session state files (`progress/[agent].md`)** — human-readable + machine-parseable observability.
10. **The `bmad-prd/SKILL.md` (92 lines)** is a masterclass in facilitation — intent modes (create/update/validate), brain-dump → stakes-calibration → working-mode routing, Fast/Coaching paths, reviewer gates.

### Ruflo's Strongest Contributions

1. **The verification/witness system is genuinely sophisticated** — 3-layer regression protection (smoke tests → SHA-256 + marker + Ed25519 signed manifest → per-OS temporal JSONL history). 55/55 fix markers verified at 100% semantic pass rate. Per-OS split because LF/CRLF causes real hash drift.
2. **CLAUDE.md (52 KB) is unusually self-aware** — explicit "HNSW Search: 150x-12,500x NOT reproduced — was brute-force fallback," "Flash Attention: Unverified (no benchmark exists)," "agentic-flow ONNX: speedup unverified." Most AI framework docs would just print the marketing numbers.
3. **MetaHarness governance (`.harness/mcp-policy.json`)** — default-deny, dangerous-pattern blocklist, `toolTimeoutMs: 600000`, `maxToolCallsPerTurn: 200`. *Enforced*, not aspirational. Architecture constraint "Ruflo remains operational if every MetaHarness package is removed" with CI gate.
4. **Dual-mode (Claude Code + Codex) coordination** with shared `collaboration` namespace is a real architectural idea executed in code (`@claude-flow/codex` package, `DualModeOrchestrator` class, `CollaborationTemplates` registry).
5. **Federation story is substantive** — mTLS + ed25519 challenge-response, 14-type PII detection pipeline, behavioral trust scoring formula `0.4×success + 0.2×uptime + 0.2×threat + 0.2×integrity`, 9 MCP tools, opt-in WireGuard mesh, circuit breaker, compliance modes (HIPAA/SOC2/GDPR).
6. **73 ADRs in `v3/docs/adr/`** is impressive discipline for a project of this velocity. They cover performance, federation, encryption at rest, plugin capability sync, BEIR benchmarks.
7. **The `ruflo/bin/ruflo.js` shim (77 lines)** has hard-won operational knowledge baked in — comments about avoiding 60-second SIGTERM timeouts from heavy dist imports.
8. **The `data/clone-data.{proof.json, ledger.json, rvf}`** — a self-attesting downloadable-metrics audit trail using the project's own RVF format.
9. **1,999 vitest tests in `@claude-flow/cli`** is a real test infrastructure — not stubs.
10. **Versatile provider layer** — Claude, GPT, Gemini, Cohere, OpenRouter, Ollama, ruvLLM (local MicroLoRA). Plus dual Claude+Codex mode.

## 4. Weaknesses — What Each Does Poorly

### Vespyr's Weaknesses

1. **`artifacts/output/` is mostly empty.** Only `02-strategy/` has content, and that content is *about* Vespyr itself (`ecc_integration_plan.md`, `ecc_integration_plan_review.md`, `ecc_skills_adoption_plan.md`, `implementation_plan.md`). No real product discovery, no PRDs, no user stories, no ADRs. The system has been used to plan itself but not (yet) to build anything external.
2. **`artifacts/memory/` is nearly empty** — 12-line `project-context.md`, placeholder `patterns-and-conventions.md`, empty `pending-questions/`, `agent-notes/`, `archive/`, `session-summaries/`. The memory engine is sophisticated but has no fuel in the tank.
3. **Some skills are thin or stale** — `grill-me/SKILL.md` is 11 lines; `squad/SKILL.md` 42 lines; `delegate/SKILL.md` 50 lines; `plan/SKILL.md` 65 lines; `code-graph/SKILL.md` 59 lines. Out of proportion with the system's grand claims.
4. **"21 agents" is partly a marketing count** — the 9 "Domain Experts" (researcher, user-researcher, ux-researcher, data-analyst, ml-engineer, security-engineer, performance-engineer, devops-engineer, technical-writer) feel like an org-chart inventory rather than carefully differentiated personas. Some overlap (data-analyst vs performance-engineer instrumentation; security-engineer vs code-reviewer).
5. **Secondary technical agents are noticeably shallower** — `ml-engineer.md` 139 lines, `devops-engineer.md` 132 lines, `data-analyst.md` 134 lines, `code-reviewer.md` 139 lines. Compare to `founder.md` 259 lines and `product-manager.md` 249 lines. The "How to build" sections read like checklists, not battle-tested workflows.
6. **The npx installer is mostly aspirational** — `implementation_plan.md` is 74 KB / 2,500+ lines; the CLI is only 2,563 lines. Plan's level of detail (16 named test cases, ASCII art spacing, 8+ transpiler engines) exceeds what the CLI currently implements.
7. **CLAUDE.md / agent.md / AGENTS.md are duplicated** — three near-identical files (~168 lines each). Should be generated by the CLI, not hand-maintained.
8. **Test coverage of the agent system itself is essentially zero** — `tests/test_cli.js` tests the CLI's transpilers and flag parser, not the 18 Node.js scripts.
9. **The "Game" pipeline is shallow** — `validate-game-idea/SKILL.md` (285 lines) and `explore-game-idea/SKILL.md` (191 lines) exist, but no `@game-designer`, no `@narrative-engineer`, no `@level-designer`.
10. **Socratic tone can be alienating** — "Tone: Bluntly honest. 'This won't work' not 'this might be challenging.'" Internally consistent with anti-sycophancy, but no opt-out tone profile.
11. **Naming/phase-numbering inconsistencies** — `phase` skill lists Phase -1: validation while folders say `00-discovery`; `06-launch/` is the launch folder but the `phase` skill table lists Phase 7 as Launch.
12. **`humanize` skill (565 lines) is sourced from a third-party repo** — will go stale unless someone actively maintains the pointer.

### ECC's Weaknesses

1. **262 skills is too many, and the smaller half is thin** — bottom 20 skills are 33–78 lines. Many are not skills but one-paragraph pointers to orchestrator engines, Itô prediction-market API, or recsys pipelines. `hipaa-compliance` (78 lines) is a thin entrypoint that says "use `healthcare-phi-compliance` for the actual work."
2. **Significant duplication risk** — three orchestrator families (`orch-*` 5 thin wrappers + `orch-pipeline` engine, `prp-*` 4 commands, `multi-*` 4 commands) for "plan → implement → commit." Legacy command shims (12 files) for backward compatibility. 26 reviewer/auditor personas (many <170 lines) overlapping with `code-reviewer.md` (323 lines).
3. **Domain sprawl** — skills include carrier-relationship-management, customs-trade-compliance, energy-procurement, inventory-demand-planning, production-scheduling, homelab-pihole-dns, homelab-vlan-segmentation, the Itô prediction-market pack, healthcare-PHI-compliance, DeFi/AMM-security, video editing, motion design. The maintainer's own consulting work is generously shared.
4. **`agent.yaml` is a maintenance hazard** — lists 145 skills, on-disk has 262. **117 skills out of sync.** A test enforces command parity but not skill parity.
5. **ECC 2.0 (alpha Rust TUI) is real but unGA'd** — `ecc2/README.md` honestly says "Do not market as done just because the scaffold builds." Two dashboards for the same conceptual product (Python TkInter + Rust TUI).
6. **`~/.claude/sessions/` data is a privacy concern** — auto-persisted session transcripts; the OpenClaw exposure story (17,470 instances) makes this high-risk by default. ECC team's defense is local-first, but local exposure is still exposure.
7. **Governance hooks are aspirational** — `pre:governance-capture` and `post:governance-capture` are opt-in, **off by default**. `pre:mcp-health-check` is the lightweight flag-pattern.
8. **Marketing-heavy README** — 5+ sponsor sections, $19/seat/mo Pro tier, Discord link, "ECC Tools" upsell, 8 language-localized READMEs. Total surface area is huge.
9. **Test coverage is uneven** — 166 test files but no automated test for skill correctness, only for YAML well-formedness.
10. **Missing adapters** — no `codeium` / Windsurf, no `continue.dev`, no `Aider` (README mentions but no `.aider/` dir), no `Tabby`, no `JetBrains AI`.
11. **Bloat: 1,487 docs files, 8 language-localized READMEs** — first-time visitor faces a wall.

### BMAD's Weaknesses

1. **Empty output folders are misleading** — `_bmad-output/` is completely empty; `design-artifacts/{A-E}-*/` are all empty; `docs/` is empty. A first-time visitor can't see any sample outputs to learn from.
2. **Module `agents/` and `workflows/` folders are mostly empty stubs** — `cis/skills/`, `gds/agents/`, `tea/agents/`, `wds/agents/`, `wds/workflows/`, `wds/tools/` are all empty. Real content lives in `.agent/skills/`, creating a confusing split.
3. **`bmm/1-analysis/research/`, `bmm/2-plan-workflows/`, `bmm/3-solutioning/`, `bmm/4-implementation/` are all empty directories.** Real bmm content is in `.agent/skills/bmad-*`. Makes the module structure look like scaffolding without substance.
4. **No top-level README.md** — a new user has to read `config.toml` to even understand what this is.
5. **4-way duplication across IDE layers** — `.agent/`, `.agents/`, `.kiro/`, `.opencode/` all contain 121 entries. Unclear if real duplicates or symlinks.
6. **`bmb-create-prd → bmad-prd` deprecation shim** suggests mid-migration to a v7 architecture; several workflows have "DEPRECATED" notices.
7. **Minimal executable code** — 2 Python scripts, 1 test, 6 Node.js scaffold scripts (WDS-only). Essentially a giant prompt library.
8. **Lots of methodology opinions baked in** — John is Marty Cagan; you can't easily opt out of this persona.
9. **Empty `custom/` config** (3 lines of comments) — no project-specific overrides demonstrated.
10. **WDS is opinionated toward web design agency work** — Norse mythology themes, Swedish/English bilingual, "client vs project owner" language. Less suitable for internal product teams.
11. **No external validation** — no documented real-world use cases or success stories.

### Ruflo's Weaknesses

1. **Extreme bloat ratio** — 1,789 TypeScript files, 1,697 Markdown files, 198 `.mjs` scripts, 5.3 MB GIF hero asset, 1.1 GB on disk. README itself acknowledges "You don't need to learn 314 MCP tools or 26 CLI commands" — which is a smell.
2. **Massive version-number inconsistency** — root `package.json` 3.14.0, AGENTS.md v3, CLAUDE.md v3.5/v3.6.10, STATUS.md 3.10.2, CHANGELOG.md "Unreleased" after 3.5.0 then skips to 3.1.0-alpha.55. Perpetual-rebranding, version-drift state.
3. **CLAUDE.md is a 50 KB instruction-prompt injection vector** — "ALWAYS use the swarm," "MUST call MCP tools AND Task tool in ONE message." Tension with `.harness/mcp-policy.json` default-deny for shell/network/fileWrite.
4. **Dual-mode is more aspirational than operational** — `npx claude-flow-codex` is an `optionalDependency` at `^3.0.0-alpha.8` that may not always install.
5. **`v3/` folder naming is confusing** — it IS the current implementation, not a "version 3 in development." Will trip up every new contributor.
6. **15 plugins in `v3/plugins/` look like stubs** — `cognitive-kernel`, `hyperbolic-reasoning`, `quantum-optimizer`, `healthcare-clinical`, `financial-risk`, `legal-contracts`. `package.json` + `README.md` but no real implementation.
7. **`agentdb.rvf` is 162 bytes** — effectively empty. The headline vector memory feature is not actually populated in this repo checkout; it gets populated at user-install time.
8. **"Ruflo" rebrand is partial** — root `package.json` is still `"claude-flow"`. `.claude/agents/` folders have stale v1.5.11/v2.0.0 references. CHANGELOG violates semver (`3.5.0 → Unreleased → 3.1.0-alpha.55`).
9. **Test coverage is uneven** — 1,999 tests in `@claude-flow/cli` but root `tests/` is 8 files. Plugin-level `__tests__` vary; some exist, some don't.
10. **MCP tool count is overcounted** — README says 314, STATUS.md 323, actual `v3/mcp/tools/` has 67. Discrepancy is a tell.
11. **HNSW performance claims walked back** — README quietly updated from "150x" to honest numbers while `v3/README.md` still claims "150x-12,500x."
12. **`v3/tmp.json` empty file** at top level — litter that should be `.gitignore`d.
13. **`v3/__tests__/security/` is small** — given all the CVE/prompt-injection claims, you'd expect a substantial security test suite.

## 9. Recommendations for Vespyr

Based on the comparative analysis, here are the highest-leverage patterns to consider adopting in Vespyr, ordered by impact/cost:

### Tier 1 — High impact, low cost (adopt quickly)

1. **From BMAD: Step-file architecture for complex skills.** Break the largest skills (`develop/SKILL.md` 278 lines, `validate-idea/SKILL.md` 299 lines, `retro/SKILL.md` 302 lines) into ordered step files loaded sequentially. Prevents LLM context drift and matches BMAD's strongest contribution.
2. **From BMAD: Tri-modal workflows (create / edit / validate).** The current `validate-idea` and `design` skills only have create flows. Adding edit/validate modes gives the user iteration power.
3. **From ECC: Code-reviewer false-positive guard list.** Add a 10+ item "Common False Positives - Skip These" list to Vespyr's `code-reviewer.md` (currently 139 lines and shallow). Costs almost nothing; dramatically improves the review experience.
4. **From Ruflo: Honest self-assessment in CLAUDE.md.** Vespyr's `implementation_plan.md` is 74 KB but the CLI is 2,563 lines. Either mark the plan as "v1.2 aspirational" with explicit status, or split into "shipped" vs "planned" sections.
5. **From ECC: Manifest with version-aware install-modules.json.** Vespyr's `bin/cli.js` could expose `npx vespyr install --modules=core,security,design` to allow users to opt out of the game pipeline or specific domain experts.

### Tier 2 — High impact, medium cost (plan carefully)

6. **From BMAD: CSV-driven technique libraries.** `elicitation/methods.csv` already exists. Extend to `brain-methods.csv` (61 techniques), `advanced-elicitation/methods.csv` (70 methods), `validation-patterns.csv`. This is BMAD's unique strength and Vespyr's `elicitation` skill is positioned to absorb it.
7. **From ECC: Cross-platform sync scripts.** Replace the duplicated `CLAUDE.md` / `agent.md` / `AGENTS.md` with a `bin/sync-docs.js` script that generates the per-harness entry-point files from a single source. Removes the maintenance hazard.
8. **From Ruflo: Verification/witness system.** When a Vespyr skill produces an artifact, hash it with SHA-256 and a marker substring. On subsequent invocations, verify the artifact hasn't been silently corrupted. Catches regressions.
9. **From BMAD: Persona-channeled mentor references.** Replace the bare "persona" descriptions with explicit "channeled mentor" attributions (e.g., `@founder` channels "Paul Graham + Marty Cagan"). Distinctive, memorable, and easy to customize via `customize.toml`.

### Tier 3 — Speculative, high cost (research first)

10. **From BMAD: WDS-style locked terminology + agent contracts.** A `references/glossary.md` with "One definition per term — no synonyms, no aliases" plus an `agent-contracts.md` with explicit "owns / does NOT own" boundaries for each persona. Would address the overlap between data-analyst/performance-engineer and security-engineer/code-reviewer.
11. **From Ruflo: HNSW vector memory for `artifacts/memory/`.** Replace the 3-tier progressive memory with AgentDB + HNSW for semantic search across `archive/`. But this is a *big* engineering bet — only worth it if memory becomes the bottleneck.
12. **From ECC: AURA-style trust integration.** A read-only Python adapter with explicit threat model for any third-party content the agent consumes (docs/, web, MCP). Currently Vespyr has no equivalent of `the-security-guide.md`.

### Tier 4 — Do NOT adopt (would dilute Vespyr)

- **Ruflo's 314-MCP-tool catalog** — Vespyr's strength is curation, not coverage. Adding MCP tools would push toward bloat.
- **Ruflo's federation / consensus stack** — Vespyr runs locally; federation is a different problem domain.
- **ECC's domain sprawl** (homelab, prediction-market, supply-chain) — these are the maintainer's own consulting work. Vespyr should stay focused on product development.
- **BMAD's WDS agency-style opinionation** — Norse mythology, Swedish/English bilingual, "client vs project owner." Doesn't fit Vespyr's product-team positioning.
- **Ruflo's "v3 is the current version" naming** — confusing; don't repeat.

## 10. Final Verdict

| Framework | Best For | Avoid If |
|---|---|---|
| **Vespyr** | Product teams who want a *focused, opinionated, Socratic* orchestrator with permission-enforced reasoning/I/O split and progressive memory. Ideal for solo PM/founder + AI pair-programming. | You need a turnkey Claude Code plugin with 9+ harness adapters, or you need 200+ domain-specific skills out of the box. |
| **ECC** | Engineering teams who need a *comprehensive, multi-platform* agent operating system with 200+ curated skills, 64 specialist agents, and 24-module selective install. | You want a small, focused skill library; the catalog depth is overwhelming and ~50% of the skills are thin entrypoints. |
| **BMAD** | Methodology-first teams who value *disciplined prompt engineering* with persona-channeled agents, step-file architecture, and locked terminology. | You need executable code; BMAD is essentially a prompt library, not a tool. |
| **Ruflo** | Power users who want a *meta-harness* with vector memory, consensus algorithms, federated agents, and dual Claude+Codex mode. | You value curation over coverage; the cognitive surface (314 MCP tools, 100+ agents, 26 CLI commands) is enormous. |

**For Vespyr's evolution, the strategic question is not "which framework to copy" but "which unique insights from each to borrow."** The four frameworks occupy four distinct positions in the design space, and the synthesis matrix above shows clear gaps where Vespyr could grow without losing its core identity.

The single most important takeaway: **Vespyr's permission-denial reasoning/I/O split is unique among the four.** This is the kind of architectural insight that's easy to miss and hard to replicate. Protect it.
