## What this skill does

Acts as your intelligent co-pilot. When you feel stuck, uncertain about the next step, or need to check project health, `help-me` performs a full diagnostic and tells you exactly what to do next.

It answers: **"What should I do right now?"**

## When to use

- `"help me"` or `/help-me` — when unsure of the next step
- `"/help-me [query]"` — targeted question about a specific phase or skill
- After a long pause between sessions — fast re-orientation
- Before running any skill — check if prerequisites are met

## Workflow

### Step 1: Load Project State

Load memory context:
```
@memory-controller load help-me [next step navigation]
```

Read `artifacts/memory/project-context.md` to determine:
- Current phase (Validation / Exploration / Design / Development / Launch / Iteration)
- Project type (startup / company / personal / game)
- Active squad (if configured in `.opencode/squads/`)
- Operation mode (`autonomous` or `semi-autonomous`)
- Active blockers

### Step 2: Load Skill Catalog

Read `.opencode/skills/help-me/skills-catalog.json` — the compiled index of all available skills with their names, descriptions, prerequisites, outputs, and key agents.

> This file is auto-generated by `node .opencode/scripts/compile_skills.js`. Re-run if you suspect it is stale.

### Step 3: Check Artifact Readiness

Check which prerequisite artifacts exist for the next likely skill:

1. Use `@reader` to scan `artifacts/output/` for present artifacts
2. Cross-reference against the prerequisite lists in the skills catalog
3. For each candidate next skill, determine: **READY** ✅ or **BLOCKED** 🚫 (list what's missing)

### Step 4: Optional — Structural Graph Check

If the user query touches codebase or document traceability:
- **Codebase graph:** Run `node .opencode/scripts/incremental_graph.js --src src/ --out artifacts/memory/structural/code-graph.json` via `@executor`
- **Document graph:** Run `node .opencode/scripts/doc_graph.js --out artifacts/memory/structural/doc-graph.json` via `@executor`
- Report any stale or missing nodes

### Step 5: Respond

Answer based on what you actually found — not a branching script. A few rules to follow:

- **Answer the question asked first.** If the user typed a specific query, address it before anything else. Source from the skill catalog, `skills.md`, or `workflow.md` as needed.
- **Be the person who checked, not the person who asks.** You just read the state. Reflect it back — don't interrogate the user about what you could have looked up yourself.
- **Point to one next step, not a menu.** If navigation is what's needed, recommend the single most logical next skill. Only surface alternatives when the choice genuinely depends on the user's intent.
- **Always surface the exact command.** When recommending a next step, end with the literal command to run it — e.g. *"Run `/explore-idea` to start research"* or *"Say `@architect` to begin architecture design"*. Don't leave the user to guess how to invoke it.
- **Match the length to the situation.** A blank-slate response is short — there's little to say. A mid-project response may need more context. A targeted question gets a direct answer.
- **Reach for structure only when it earns its keep.** Prefer prose. Use a list or table when there are 3+ parallel things that genuinely need comparison — not as a default.
